# 简历匣 V1 设计

## 产品目标

让个人用户把一份已有简历整理为可复用资料，并在不同招聘网站填写相同内容。核心闭环是：**PDF → 可审核的文本模块 → 本地资料库 → 网页字段匹配 → 填充 → 新答案记忆**。

V1 追求明确、可检查的匹配。无需注册或配置模型服务。不能判断的字段由用户补充，不从其他经历猜测答案。

## 页面与用户流程

侧边栏提供三个入口：网页填充、我的资料、使用说明。它可常驻在申请表单旁，不需要在网页和独立编辑器之间来回切换。

### 首次整理简历

1. 选择或拖入 PDF，完全在本地提取文本；也可粘贴已有简历文字。
2. 按章节标题归类个人简介、教育经历、工作经历、项目经历、专业技能及证书奖项。
3. 对明确的姓名、邮箱、电话、个人链接或“字段：内容”提取独立条目；其余文字保留为待整理内容。完整提取文本可在导入审核窗口查看。
4. 展示草稿，允许逐条修改分类、名称、内容和是否保存。
5. 仅新增已勾选的内容，不覆盖资料库已有记录。相同名称且相同内容的记录不重复保存。

不同内容的同名记录允许并存，以保留多个学校或经历；匹配时遇到同等候选不会擅自决定。

### 填写网站

1. 用户在目标网页点击扩展工具栏图标，获得当前网站的临时访问权限。
2. “识别网页”仅扫描主文档中可见且可编辑的控件，展示识别数、匹配数、待补充数。
3. 每条字段展示网页名称、控件类型、所属分组、匹配来源、可编辑的答案和“记住答案”选项。可从资料下拉列表手动绑定其他条目。
4. 高确定性且网页原值为空的字段默认勾选。重复字段、模糊候选、不兼容选项及复杂控件不默认填写。
5. 用户点击“一键填充”，只写入已选择且有答案的字段。已有资料时，“识别并填充已知资料”把识别与明确匹配项的填充合并为一次操作。
6. 新问题输入答案后自动勾选该条；成功填充且勾选“记住答案”时保存本地记录。用户也可单独保存勾选答案，不写网页。

默认保护网页原有内容，覆盖需要显式勾选“允许覆盖网页已有内容”，并选择要覆盖的具体字段。即使允许覆盖，也会保留在扫描后被用户或网站新修改的值。

### 维护资料

资料库支持分类、搜索、增删改、自定义别名及备份恢复。资料被修改或删除后，清除已有匹配清单，要求重新识别，避免填入旧快照。

删除某条资料会同步删除关联记忆。清空和恢复备份会先展示具体影响并确认。备份包括所有资料和问答记忆，不包括原始 PDF。

## 数据模型

| 对象 | 关键字段 | 用途 |
| --- | --- | --- |
| ProfileItem | id、label、value、category、aliases、source、updatedAt | 独立文本资料；经历可保存为多行文本 |
| Memory | signature、itemId | 将特定问题绑定到资料条目 |
| Store | version、items、memories、updatedAt | 版本化本地数据和备份格式；更新时间也用于冲突检测 |
| PageField | id、label、hints、context、signature、kind、currentValue、options、repeated | 单次扫描的字段快照 |
| FieldDraft | field、itemId、value、selected、remember、match、outcome | 用户确认中的填充草稿，仅保留在界面内存 |

分类包括：基本信息、个人简介、教育经历、工作经历、项目经历、技能证书、其他资料、问答记忆。数据值统一为文本；下拉和日期在写入时转换，不向基础资料层引入网站特定控件格式。

## 解析与匹配规则

### PDF

使用随扩展打包的 PDF.js 和 Worker 获取每页文字项，通过文字坐标恢复换行与间距。按常见中英文标题归类，规则识别基本信息。导入审核是必要环节；V1 不声称能正确恢复任意多栏 PDF 的阅读顺序。

限制为 20 MB、30 页。密码文件提示解锁，损坏文件提示重新导出，提取不到足够文字时提示扫描件不支持 OCR，并提供文本粘贴方式。PDF 不保存在本地资料库。

### 字段名称与语境

字段名称优先级：`aria-labelledby` → `aria-label` → 原生 label → 常见表单容器标签 → placeholder → name → id。下拉框 label 提取时排除其选项文本。辅助线索来自 name、autocomplete、placeholder、id；优先尊重人类可读的标签。

分组优先读取 fieldset 的 legend 或 section 的标题，并归一为教育、工作、项目等语境。问题签名为“语境 + 标准化标签”；标准化统一全半角、大小写、空格和标点。仅有内部 name/id、缺少可读标签和提示的字段，其记忆限定在当前网站；完全没有名称的字段只做本次填写。

匹配顺序：

1. 精确问题记忆，且引用条目仍存在。
2. 资料名称与别名的精确匹配。
3. 内置中英文同义词，如电子邮箱 / email address、最高学历 / degree。
4. 多个同等候选、重复字段或无可靠线索时转为待补充。

问答来源的条目按其问题签名或用户明确添加且语境相同的别名复用，不参与脱离语境的普通名称匹配；避免教育“开始时间”被填进工作“开始时间”。手动维护的普通资料可通过别名定义跨网站的同义关系。V1 不使用相似度阈值或模糊子字符串猜测。

## 控件能力

| 控件 | V1 行为 |
| --- | --- |
| input 文本 / email / tel / url / number 等 | 原生 value setter 写入，触发 input、change；检查格式与长度 |
| textarea、普通 contenteditable | 写入纯文本并触发事件；适合经历和介绍模块 |
| 原生单选 select | 仅匹配唯一且可用的 option 标签或值；不匹配时由用户明确选择 |
| 原生 date / month | 归一化日期分隔符，验证实际年月日，写入 ISO 日期或月份 |
| 自定义 combobox / 日期弹层 / 富文本编辑器 | 提示手动处理；没有通用可靠适配 |
| checkbox、radio、文件、密码、验证码等 | 跳过 |
| iframe、Shadow DOM、分页动态表格 | V1 不深入扫描；提示在新标签页打开内嵌表单或重新识别 |

## 架构

```text
侧边栏 panel
  ├── PDF.js Worker → 解析 / 规则归类 / 草稿审核
  ├── 本地资料编辑与字段匹配
  ├── background service worker → 串行保存 → chrome.storage.local
  └── activeTab + scripting → content script
                               ├── DOM 扫描与字段快照
                               ├── 受控写入、事件和结果校验
                               └── 上次写入快照 / 条件撤销
```

- Manifest V3，仅申请 sidePanel、storage、activeTab、scripting。
- 工具栏采用显式 action.onClicked 打开侧边栏，使浏览器正常授予 activeTab；不使用可能消耗点击而未授权的侧边栏自动开关行为。
- PDF 解析及网页匹配不依赖联网模型，全部依赖随扩展打包。
- 完整资料库仅向扩展可信上下文开放；content script 只接收选中的写入值。
- 扫描与写入绑定 tab、document、URL、单次 token 和具体 DOM 引用。切换标签、导航、节点被替换、字段语义或值变化时拒绝过期操作。
- 保存由 service worker 串行执行，利用时间戳版本检测多窗口冲突，避免静默覆盖。
- 填充结果与保存结果分别报告；网页写入成功但本地保存失败时明确提示，不误报全部成功。
- 撤销只恢复最后一批成功写入且未被后续修改的值，不点击提交、不主动捕获网站手动输入。

## 验收场景

1. 文字版中英文简历能生成可修改的模块，未归类文本保留；重复导入不会生成完全相同的记录。
2. 标准表单可识别姓名、邮箱、长文本、原生下拉和日期，并正确触发页面事件。
3. 新问题回答并保存后，刷新或再次打开页面可自动匹配。
4. 同名教育和工作问题的记忆相互隔离；重复经历字段不自动选择。
5. 默认不覆盖已有输入；扫描后的手动修改即使开启覆盖也受保护；撤销保留后续修改。
6. 修改、删除、备份和恢复后，资料与记忆引用保持一致。
7. 在真实 MV3 环境原样加载生产 manifest，验证中英文 PDF、Worker、CSP、storage、脚本注入和导航后复用；通过 Chrome DevTools Protocol 触发工具栏 action 验证临时授权。

## 后续迭代

下一版优先引入学校、公司、职位、起止时间等结构化经历与条目序号，解决“多段经历 → 网站重复表格”的映射。之后按实际使用的网站增加自定义控件适配，并考虑可选 OCR、同义问题建议和用户主动开启的模型解析。云同步、多设备账户和自动提交不属于 V1。
